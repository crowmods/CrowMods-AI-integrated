# Phase 139

## Row-level SQL purge locks
The database policy exposes allowlisted row selection with retention predicates
and `FOR UPDATE SKIP LOCKED`, enabling concurrent workers to avoid claiming the
same rows.

## Alert recovery cooldowns and escalation caps
Recovery can be suppressed during a cooldown window, while repeated escalation
is bounded by an explicit cap.

## Lease-to-checkpoint transaction binding
A calibration checkpoint is associated with the owner and fencing version that
authorized it, providing a durable audit relationship.

## Manifest verification idempotency
An idempotency key prevents duplicate processing and detects accidental reuse
of a key for a different export.

## Security boundary
Purge handlers remain allowlisted and should use table-specific parameterized
SQL. Idempotency keys should be generated by trusted callers and stored with
appropriate uniqueness constraints.
